# 微信公众号侧限制与排障

## 1. 只创建草稿，不自动群发
当前实现只会调用草稿接口，不会自动群发。

## 2. IP 白名单
如果调用 `get_access_token` 失败，并看到类似 `invalid ip not in whitelist`：
- 去公众号后台添加当前出口 IP 到白名单

## 3. 标题长度限制
微信标题有长度限制。
当前实现已经做了两层处理：
- 生成阶段要求输出 `new_wechat_title`
- 发布阶段会优先使用 `new_wechat_title`

如果仍报标题过长：
- 检查 `article.json` 中的 `new_wechat_title`
- 尽量控制在 12-16 个汉字，最长不超过 18 个汉字

## 4. 摘要长度限制
摘要过长会触发微信接口报错。
当前实现会优先取 `new_summary`，必要时应进一步精简。

## 5. 中文乱码
如果标题、作者或正文显示为 `\uXXXX` 形式：
- 检查请求是否使用 `ensure_ascii=False`
- 检查请求体是否按 UTF-8 编码发送

当前实现已按 UTF-8 发送微信 JSON。

## 6. 图片不显示
现在真实发布流程不再依赖 GitHub 图床显示正文图片。

当前策略：
- 正文图片直接上传到微信 `media/uploadimg`
- 封面图上传到微信素材接口

所以如果正文图片不显示，优先检查：
- 图片上传是否成功
- 最终正文 HTML 是否已替换成微信返回的 `mmbiz.qpic.cn` 地址

## 7. dry-run 和真实发布的区别
### dry-run
- 主要用于本地预览 HTML
- 可能仍会使用 GitHub Pages 链接帮助预览
- 不代表真实草稿里的正文图片来源

### 真实发布
- 正文图片来自微信图片接口
- 封面图来自微信素材接口
- 不再依赖 GitHub 图床

## 8. 推荐排障顺序
1. 先跑 `--dry-run` 看 HTML 是否正常
2. 再看正文图片 URL 是否已经替换成微信地址
3. 再看微信接口响应是否成功
4. 最后去公众号后台草稿箱确认显示效果
